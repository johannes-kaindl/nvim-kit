# Conformance vectors and exported data

Generated by `npm run build:conformance` from the TypeScript modules — do not edit by hand. `npm test` fails until the committed files match what the modules compute (`tests/conformance.test.ts`); the inputs live in `tests/conformance/build.ts`, the expected values are always computed, never written.

Each `<function>.json` holds `{ schema, function, cases: [{ name, args, expected }] }`. A port of the same logic in another language (first consumer: `nvim-kit`, Lua) vendors these files and must pass every case — this is the fixture rule in `AGENTS.md`. No case carries a `null` inside an array; a top-level `null` in `args` means "not set".

`../data/sampling-profiles.json` holds the tables of `sampling-profiles.ts` (families, modes, backends, family patterns, ranges). Family patterns use only literal characters, `\.`, a character class of literals and `?`, with flag `i`; a port translates them into its own regex engine on that basis, and a test here keeps new patterns inside that subset.

## Notes for ports

Family patterns: Lua patterns have no case flag and treat `-` outside a class as a quantifier. Lowercase the model name (every pattern is lowercase), write `gpt-oss` as `gpt%-oss` and `\.` as `%.`, or translate the pattern to `vim.regex` instead.

A `null` inside an object means the key is absent (in Neovim: `vim.json.decode(s, { luanil = { object = true } })`); a top-level `null` in `args` arrives as `nil` at its position.

An empty object `{}` and an empty list `[]` are different values in `expected` (e.g. `settings.overrides: {}` next to `dropped: []`); a port's comparison has to keep them apart.

`firstJsonObject` follows the strict `JSON.parse`: `NaN`, `Infinity`, hex numbers and leading zeros are no JSON, so the next span wins. A lenient decoder (`vim.json.decode` accepts all four) cannot be the port's only judge.

`dropped` from `sanitizeRequestSettings` is sorted in code-unit order (JS `sort()`); for the ASCII paths here that is byte order. Lua's `<` on strings uses the locale's collation, so a port compares bytes instead.

What JSON cannot carry is in no vector: `NaN`, `Infinity`, `-0`, `undefined`. `validateOverride("temperature", NaN)` is `null` in TS, and a plain range check in another language lets NaN through — a port tests such inputs itself.
